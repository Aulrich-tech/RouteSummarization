1. What is route summarization?

Route summarization (also called route aggregation or supernetting) replaces many specific routes with one summary route that covers all of them. Instead of telling a neighbor router about 16 separate networks, you say “send me anything in this one big block.”

Real-life analogy: A courier company doesn’t keep a separate rule for every house on every street in Quezon City. They keep one rule: “anything for Quezon City goes to the QC hub.” The hub handles the details. Summarization works the same way: the upstream router only needs the big block, and the router that owns the networks handles the specifics.

Advantages

  • Saves memory: smaller routing tables need less RAM.
  • Saves bandwidth: fewer routes to advertise means smaller routing updates.
  • Saves CPU cycles: fewer packets to process and smaller tables to search.
  • Stability: if one /24 inside the block keeps going up and down (“flapping”), the summary stays up, so other routers aren’t forced to recalculate again and again.
Situation: A branch router has 16 LANs (172.16.0.0/24 to 172.16.15.0/24) and connects to the head office router over one WAN link. Without summarization the head office has 16 routes for this branch. With it, the head office has one route: 172.16.0.0/20. If the 172.16.9.0/24 LAN flaps, the head office never notices, because the summary still stands.

2. How to calculate a summary route

  1. Convert the addresses to binary and line them up in a list. (Only the octet where the networks differ matters. The earlier octets are the same.)
  2. Find where the common pattern ends. Look from the left for the last bit that is the same in every address.
  3. Count the common bits. The summary is the first (lowest) network address, then a slash, then the number of common bits.
Shortcut: Count how many networks you have. If it’s a power of 2 (2, 4, 8, 16…), the number of host-side bits you give up is log₂ of that count. New prefix = old prefix − bits given up. 16 networks of /24 → 4 bits → /20.

Bit values of an octet

128 · 64 · 32 · 16 · 8 · 4 · 2 · 1. Memorize these. Every example below uses them.

3. The block-size rules (very important)

Networks can only be combined into a summary when they form a clean, aligned block. The block size must be a power of 2, and the starting address must be a multiple of the block size.

Situation: You have 172.16.4.0/24 up to 172.16.11.0/24 (8 networks). It looks neat, but 4 is not a multiple of 8, so they cannot become one /21. A /21 block starts at 0, 8, 16, 24… So you’d split it: 172.16.4.0/22 (4–7) and 172.16.8.0/22 (8–11).

4. Worked examples

Example 1: 16 networks → /20

172.16.0.0/24 through 172.16.15.0/24. Only the 3rd octet changes:

172.16.0000 0000.0   (0)
172.16.0000 0001.0   (1)
   ...
172.16.0000 1111.0   (15)

First 16 bits (172.16) + first 4 bits of the 3rd octet (0000) are common = 20 bits. The last 4 bits of that octet run through 0000–1111, which is exactly 16 networks.

Summary: 172.16.0.0 /20

Example 2: Two extra networks join (16.0 and 17.0)

Now add 172.16.16.0/24 and 172.16.17.0/24 to the list. Can we make one /19 or so? No: 16 and 17 start at 16, and 0–15 is already its own clean block. The best approach is two summaries.

172.16.0001 0000.0   (16)
172.16.0001 0001.0   (17)

Common bits: 16 + 7 = 23 (only the last bit of the 3rd octet changes).

Summaries: 172.16.0.0 /20 and 172.16.16.0 /23

Why it matters: never stretch a summary to cover networks that aren’t yours. A bigger /19 would advertise 172.16.18.0 to 172.16.31.0 too, and traffic for those would come to you and get dropped.

Example 3: /28 subnets → /26

192.168.10.128/28, .144/28, .160/28, .176/28 (arranged in order). Only the last octet changes:

192.168.10.1000 0000   (128)
192.168.10.1001 0000   (144)
192.168.10.1010 0000   (160)
192.168.10.1011 0000   (176)

24 bits (192.168.10) + 2 common bits (10) = 26. Four /28 blocks (16 addresses each) = 64 addresses = a /26.

Summary: 192.168.10.128 /26

Example 4: /22 blocks → /21

172.16.184.0/22, .188.0/22, .192.0/22, .196.0/22

172.16.10111 000.0   (184)
172.16.10111 100.0   (188)
172.16.11000 000.0   (192)
172.16.11000 100.0   (196)

The first two share 10111 (5 bits) → 16 + 5 = 21. The last two share 11000 → also 21. But 10111 and 11000 differ at the very first bit, so all four cannot become one route.

Summaries: 172.16.184.0 /21 and 172.16.192.0 /21

Example 5: Same size blocks, spacing of 8

192.168.0.1100 0000   (192)
192.168.0.1100 1000   (200)
192.168.0.1101 0000   (208)
192.168.0.1101 1000   (216)

Only the last 5 bits change, 3 bits are common: 24 + 3 = 27.

Summary: 192.168.0.192 /27

Example 6: Networks that don’t line up

192.168.0.0101 1100   (92)
192.168.0.0110 0000   (96)
192.168.0.0110 0100   (100)
192.168.0.0110 1000   (104)

92 is not at a clean boundary relative to 96–107, so one tidy summary would swallow addresses that aren’t part of the group. The result is a few exact routes:

192.168.0.92 /30, 192.168.0.96 /29, 192.168.0.104 /30

Example 7: Summarizing in layers (mixed sizes)

Start with 192.168.10.0/27, .32/28, .48/28, .64/26, .128/25.

  1. .32/28 + .48/28 (0010 0000 and 0011 0000 share the first 3 bits “001”, so 24 + 3 = 27) → 192.168.10.32/27
  2. .0/27 + .32/27 (0000 0000 and 0010 0000, 2 common bits) → 192.168.10.0/26
  3. .0/26 + .64/26 (0000 0000 and 0100 0000, 1 common bit) → 192.168.10.0/25
  4. .0/25 + .128/25 (0000 0000 and 1000 0000, 0 common bits in this octet) → 192.168.10.0/24
Final summary of everything: 192.168.10.0 /24

Example 8: Mixed /24s, /23s and /21 → /20

172.16.32.0/24, 33.0/24, 34.0/23, 36.0/23, 38.0/23, 40.0/21

  • 32.0/24 + 33.0/24 → 172.16.32.0/23
  • That /23 (32–33) + 34.0/23 + 36.0/23 + 38.0/23 cover 32–39 → 172.16.32.0/21
  • 40.0/21 covers 40–47. Together 32–47:
172.16.0010 0000.0   (32)
172.16.0010 1000.0   (40 block)
 … up to 172.16.0010 1111.0   (47)
Final summary: 172.16.32.0 /20

Example 9: A real-life campus situation

A school has 4 buildings, each with its own subnet: Library 192.168.20.0/26, Science 192.168.20.64/26, Admin 192.168.20.128/26, Gym 192.168.20.192/26.

Last octet starts: 0, 64, 128, 192 → 00, 01, 10, 11. All 2 leading bits are used, so zero bits are common in that octet: 24 + 0 = 24.

The ISP router needs only 192.168.20.0 /24. Four routes became one.

5. Common mistakes

  • Using a non-power-of-2 count. 6 networks can’t be one clean summary. Group them as 4 + 2.
  • Wrong start address. Summary must start at the lowest network address, and it must be aligned to the block size.
  • Over-summarizing. A summary that covers networks you don’t own can black-hole traffic.
  • Mixing up “prefix − bits”. 8 networks of /24 → /21 (24 − 3), not /27.
  • Only comparing the first and last address by decimal. Always check in binary for where the pattern breaks.
